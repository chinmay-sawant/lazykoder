One home for Compaction and fill policy

9/10 Strong in-process

internal/agent/compact.go · compact_run.go · history.go · internal/settings/settings.go · internal/ui/chat/transcript.go · picker.go · keys.go · internal/subagent/runner.go

Before

After

Problem

Fill math and Compaction thresholds live in agent, settings, and the TUI at once. Defaults are duplicated. serializeEntries ignores KeepTokens. Child auto-compact is a no-op.

Solution

One Compaction module owns estimate, threshold, reason, envelope, and history apply. Settings store knobs. UI paints from exported helpers.

Wins

  • locality: one threshold home
  • leverage: UI + Agent share NeedsCompact
  • keep_tokens bug dies once
  • child Options match reality
  • ForceCompact wired or deleted

Extract turn-runtime from chat.Model

9/10 Strong ports & adapters

main.go · internal/ui/chat/chat.go · keys.go · settings.go · internal/agent · internal/subagent · confirm/ask hooks

Before · mass

interface: Model fields (~165) + agentOptions + submit/runCompact/resume
implementation: Manager boot, Host, Confirm/Ask channels, Agent.New, pulse, busy, rebuildSubMgr

shallow: interface nearly as wide as the wiring pile

After · mass

interface: start turn / compact / continue / cancel / watch
implementation: Manager lifecycle, Host, gate adapter, Agent options, event pump

deep: TUI only paints and routes keys

Problem

chat is the composition root and the view. submit, runCompact, and resumeAfterLimit re-copy Agent wiring. Settings rebuild Manager mid-TUI.

Solution

A turn-runtime module owns Manager, Host, Confirm/Ask adapters, and Agent construction. Chat calls a narrow seam via tea.Cmd.

Wins

  • locality: one boot ritual
  • leverage: tests fake runtime
  • chat_test.go can shed wiring cases
  • gate adapter reusable for children
Constraint: keep Update pure; side effects stay in tea.Cmd. Do not invent a multi-provider interface (decisions.md: OpenCode Go only).

Wins

  • pulse stops knowing drawer guts
